# 并行推进操作指南

## 最小角色与职责

| 角色 | 负责 | 不负责 |
|---|---|---|
| 主任务 | 定义总量与依赖，发短任务，平衡产能，核接口，唯一正式合并 | 重做每个包的专业判断，反复全文重审 |
| 生产者 | 根据准确输入完成一个可交付范围，保存结论和证据 | 决定全项目方向，修改他人稿或正式总表 |
| 独立核查者 | 检查指定版本，定位错误、遗漏及适用限制 | 泛泛重做全域研究，替生产者悄悄改稿 |
| 专项决策／裁决者 | 高风险、争议或项目规定的最终取舍 | 给机械搬运重复签署，替同一身份自审 |
| 整理与验证 | 结构整理、确定性检查、归并准备、差异定位 | 越权改变含义、科学结论或设计取舍 |

小项目可减少角色。对要求独立性的判断不能由同一任务改个角色名称来充数。主任务如果写了专业结论，就不能同时自称那份结论的独立审查者。CI run ID 是协调身份，不代替 CLI 事件中的真实任务 ID。

## 先有可控总量，再派工

把已知范围定义为有限的文件、模块、研究问题、数据分区、对象或交付包，并说明“完成”的领域含义。新增发现单独说明是否影响当前目标，不自动变成无穷新任务。探索性研究可以没有事先可证明的发现总量，但要有时间／问题边界、可交付结论和剩余不确定性。

至少区分：输入已处置、产物已完成、独立核查通过、正式交付。不同分母分开报，不用一个漂亮百分比掩盖下游积压。完成所有枚举输入只能证明清单覆盖，不证明宇宙范围的无遗漏。研究结论的证据强度与工程测试的实际覆盖要另说清。

分包以可独立判断、可独立交接为准。不要机械地按等字数切开强依赖内容，也不要让某个包无限等待“完整大稿”。过长任务在下一安全点交出已有成果，再拆明确未完范围；不重做已经完成的部分。

## 上下文只带当前需要

辅助输入仅包含：目标、准确范围、有效输入与版本、必要领域规则、输出位置及停止条件。协调者看全局快照，辅助不读全局施工历史。历史只在某个依赖缺失时定位阅读。

输入可用仓库 commit、不可变文件或内容哈希固定；不要只给会被覆盖的“最新文件”路径。传入 --policy 的短规则与 prompt 会在派工时冻结到每个 job/prompt.txt，但外部引用的源码、论文或数据并不会被启动器自动快照。主任务需按风险提前复制或锁定它们，并保留必要条件、证据、反例和版本信息。

摘要可以导航，不能冒充审查对象本身。审查者必须拿到需核查的完整有效内容。长命令只返回差异、错误和定位，避免把全量表或整本日志倾倒进模型上下文。已知正确且未变的内容继承，不再次全文扫描。

## 就绪驱动与滚动接续

一次调用只提交当前可立即执行的任务，prompts 数不能超过 workers，不在启动器里藏长队列。每份任务结束立即打印一行完成通知；其 request.json 与 result.md 可单独接收，不必等 summary.json。summary.json 在该调用所有任务结束后写出。

生产／核查／决策／整理可分别起不同批次，主任务在现有会话按就绪产物接续。启动器不自动把结果投给下一角色，不互投 prompt，不开常驻监控。想让主任务继续调度，使用当前环境支持的后台进程方式或终端会话；Windows 后台启动须隐藏窗口并分别保存 stdout/stderr。不要增加定时服务来替代正常交接。

同一输出只允许一个写入者。其他任务只交自己的差分或候选。若工程项目已经有 PR／分支合并流程，就用现有流程作唯一合并出口，无须再建一套表。需要编号或共享键时集中分配，不能让并行任务各自猜编号。

随读保存的是有意义的成果和未完边界，不是每一步思考日志。中途 handoff 要列准确文件和版本；读取者先核其稳定性，不能边被上游改写边宣告验收。正式交审后冻结，被锁稿不能原地覆盖。

## 怎样决定扩容与模型

先看可执行积压在哪一段。生产草稿很多而独立核查少，优先给核查槽位；核查已齐而未合并很多，增加整理与接口验证，或把已明确范围的终裁下放给合格独立角色。主任务仍保留全局组合和正式写入，不成为所有专业判断的串行瓶颈。

只有存在足量互不冲突的就绪任务、下游能接收、资源未饱和时才扩容。用少量已完成批次的有效交付速度、返工原因与积压变化判断，不追求 CPU 或槽位全部占满。高并发可能受服务限流、额度、网络、磁盘、锁争用和上下文大小限制；单个任务变慢不能直接归因带宽。先定位错误／等待发生在哪里。

模型不固化到代码：重复、边界清楚的整理与筛查可用较低成本模型；专业推理、独立审查与争议裁决用更强模型及足够 effort。难度相同的任务可以同档配置，升档也不能代替好证据和好分包。原实践曾按角色使用 Luna/max 与 Astra/xhigh，但这是一个配置样例，不代表目标账户可用或任意领域最优。

用真实有效产物衡量质量。先诊断任务定义、证据、工具和模型能力，再决定升模型还是拆任务；不要盲目同时扩大输入、并发和 effort。记录 requested_model 与 requested_effort，本启动器不从这些参数推断服务端实际模型或账单。

## 减少收尾的重复劳动

在最终内容冻结前完成可提前做的机械检查：路径、键、必需字段、引用、格式、依赖版本、测试入口、安装条件。未取得的批准或证据保持未取得，不能为消除验证报错填假值。

机械候选准备不等于新一轮专业研究。专业生产者确认准确内容后再锁；独立核查与机械检查可对同一锁稿并行；必要裁决读完整有效链并明确采用、返工或有据保留。把已经判定的限定条件准确搬到交付中，不在“精简”时删掉。

局部修改只使真实受影响范围和依赖失效。新字节不能继续冒用旧签名；未变有效部分也不应自动全量重审。项目级收口检查跨包一致性、覆盖与组合，不再次逐项重研究。包级与项目级若确有不同职责可分别保留，否则不要套用额外验收层。

## 暂停和恢复

自然暂停：主任务停止新派工，让已启动的有限批次到交接点结束；核实所有本项目进程停止，记录已完成和未完成，不自动复工。参考启动器没有在线暂停 RPC；stdin 输入任务后关闭，不向运行中的临时任务假装发送新指令。

紧急停止：前台 Ctrl+C 会停止本调用并终止它记录的活动子进程；超时同样按本 job 终止，保存已有文件且不自动重试。Windows 使用精确 PID 的进程树结束，不扫描全机“同名进程”批量杀；POSIX 使用本调用建立的进程组。硬停止不是无损暂停，保存未写完的文件可能不完整。

宿主崩溃、强杀或机器掉电不保证自动清理。遇到 running 遗留标记，先核对 PID、启动时间、命令行与该 job 的归属，避免误伤复用 PID；查完再确定是否停止。request.json 不是可靠的实时存活探针。日志、部分产物和非零退出都应保留诊断，不直接删掉失败目录。

恢复时创建新批次目录、新的真实任务身份，只指定上次未完或受影响范围。引用已有交接，检查输入是否变化，不覆盖旧锁稿、不重跑已完成工作。--ephemeral 不是会话持久化；本架构的接续依据是成果，不是隐藏对话历史。

额度策略留在用户授权的协调层。不要让所有辅助分别记预算，也不要自动部署预算监控或设置通用阈值。工具与服务限制不能靠权限开关绕过。

## 跨领域迁移

| 领域 | 输入单元与产物 | 合理的独立验证 | 需要目标项目决定 |
|---|---|---|---|
| 工程 | 互斥模块／补丁、复现用例 | 单元／集成测试，接口和安全审查 | 可写工作树、运行环境、合并策略 |
| 科研 | 问题、文献证据、实验或数据分区 | 原始来源核对、复现、统计方法检查 | 数据权限、计算预算、科学结论标准 |
| 数据整理 | 分区、映射、异常记录 | schema、守恒、重复键与有风险项复核 | 容错标准、隐私边界、回滚 |
| 内容与设计 | 概念包、稿件或候选 | 事实、目标受众、风格和可用性检查 | 评价依据、必要主观取舍 |
| 开放探索 | 有界问题与证据簇 | 反例、替代解释、结论强度审视 | 停止条件，不承诺穷尽发现 |

最低启动流程：指定授权范围与交付标准 → 填一页当前入口 → 固定第一批输入 → 两路小规模闭环 → 找真实积压后扩容。目标机器的主任务可以从 templates/coordinator-entry.md 接管，不需要原项目历史。
